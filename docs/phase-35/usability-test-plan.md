# Phase 35 — Usability Test Plan

## Status: NOT YET VALIDATED WITH REAL USERS

Stated plainly, per this mandate's own explicit instruction: no real
user has been tested against this or any prior phase's plan in this
engagement. Nothing in this document is a finding. This session will
not write fictional results, quotes, or success rates.

## Relationship to `docs/phase-34/usability-test-plan.md`

That plan remains valid and is not superseded — this phase's task list
is a close variant (Section 22's own wording), reproduced here verbatim
for this phase's own record rather than only cross-referenced, since the
mandate explicitly asked for it created fresh.

## Tasks

1. Find Safe-to-Spend.
2. Explain what it means, in your own words.
3. Explain why it differs from your account balance.
4. Find your biggest spending category.
5. Find your upcoming bills.
6. Create a transaction (any type).
7. Edit that transaction.
8. Find your Available Credit.
9. Find your Investments.
10. Find your Net Worth.
11. Create a budget.
12. Create a goal.
13. Explain whether that goal is on track, and why.
14. Ask Spensa a question you'd actually want answered.
15. Turn Privacy Mode on.
16. Confirm, in your own words, that financial information is now
    hidden — and where.

## Recording template (per task)

| Field | What to capture |
|---|---|
| Task | Number/description |
| Success / Failure | Completed unaided, yes/no |
| Time | Seconds to completion or giving up |
| Hesitation | Pauses, backtracking, re-reading |
| Error | Wrong click/page needing correction |
| Misinterpretation | Any statement revealing a wrong mental model |
| Quote | Verbatim only |
| Confidence (1-5) | Self-reported after the task |
| Severity if failed | P0 (couldn't do it at all) / P1 (did it, confused) / P2 (minor friction) |

## Anti-fabrication guardrails

- No "expected result" is written in advance for any task.
- An incomplete session is recorded as incomplete, not as a partial pass.
- Any aggregate percentage must be reported alongside its real sample
  size (n=), never presented bare.

## What this phase can honestly report instead

This session performed its OWN structured walkthrough of a fresh
account this phase (signup → onboarding → add a bank account → add a
credit card → create a transaction → inspect Cash Flow → inspect the
transaction detail sheet → delete the account) to verify functional
correctness and reference fidelity. That is engineering/QA verification,
not user research, and is reported as such throughout this phase's
documentation — never conflated with the real usability-testing task
list above.
