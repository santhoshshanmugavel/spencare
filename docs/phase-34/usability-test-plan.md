# Phase 34 — Usability Test Plan

## Status: NOT YET VALIDATED WITH REAL USERS

Per Section 30's explicit instruction, this is stated plainly and
without hedging: **no real user has been tested against this plan.**
Nothing below is a finding — it is the instrument to be run, not results.
No success rates, quotes, hesitation points, or confidence scores are
reported anywhere in this engagement's documentation, because none were
observed from an actual person. Any document that appeared to claim
otherwise would be fabricated research, which this session will not
produce.

## Participants

5–10 people who manage their own personal finances day-to-day, ideally
including at least one person unfamiliar with budgeting apps generally
(not just this product) — the mandate's own "first-time financial-
product user" framing depends on a genuinely fresh perspective.

## Setup

A seeded test account with realistic (not empty, not extreme) data: 2–3
accounts across at least Bank + Credit Card, ~2 months of transaction
history, one active budget, one goal roughly at the halfway point. Each
session starts logged in on that account, not from signup, unless
testing onboarding specifically is the goal of that session.

## Tasks

1. Find how much money you can safely spend right now.
2. In your own words, explain what that number means and how it's
   different from your account balance.
3. Find your biggest spending category this month.
4. Find your monthly cash-flow trend (is income up or down vs. last
   month?).
5. Find your upcoming bills.
6. Create a budget for a category of your choice.
7. Apply that budget to upcoming months (not just this one) — and
   explain, in your own words, what "apply to upcoming months" actually
   changes vs. what stays the same.
8. Create a savings goal using the guided flow.
9. Explain, in your own words, whether you're on pace for that goal and
   why.
10. Find how much available credit you have.
11. Find the value of your investments.
12. Find your Net Worth.
13. Ask Spensa one real financial question you'd actually want answered.
14. Turn on Privacy Mode, confirm you can't read the real numbers
    anymore, then turn it back off.

## What to record per task (template)

| Field | What to capture |
|---|---|
| Task | The task number/description above |
| Success / Failure | Did they complete it without being told the answer? |
| Time | Seconds from task start to completion or giving up |
| Hesitation | Any pause >5s, backtracking, or re-reading |
| Error | Any wrong click/page that had to be undone |
| Misinterpretation | Any moment they said something that revealed a wrong mental model (e.g., calling Safe-to-Spend "my balance") |
| Quote | Verbatim, only if actually said |
| Confidence (1–5, self-reported) | Ask after each task: "how confident are you that's right?" |
| Severity if failed | P0 (couldn't complete at all) / P1 (completed but confused) / P2 (completed, minor friction) |

## Explicit anti-fabrication guardrails for whoever runs this

- Do not write a "typical result" or "expected outcome" row before
  running a session — that would bias both the running and the write-up.
- If a session is cut short or a participant disengages, record it as
  incomplete, not as a partial success.
- Aggregate numbers (e.g., "80% success on Task 1") are only valid once
  the actual session count is stated alongside them (n=5 is not the same
  claim as n=50).
